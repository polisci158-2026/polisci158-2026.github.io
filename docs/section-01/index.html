Three ideas before you start

1 · A chat model gives you text. A coding agent does work in a folder.

In a regular chat (claude.ai, ChatGPT), you ask a question, get an answer, and copy what you need. A coding agent works inside a folder on your computer. It can read your files, create and edit them, and run commands. It shows you what it changed, and it asks before doing anything risky. You describe the goal, and you stay the reviewer.

3 · Why Git and GitHub?

Without version control you end up with files like index_final_v2_REAL.html. And when an agent rewrites your page and breaks it, there's no way back. Git solves both problems.

Git is a tool on your laptop. It records the versions of a folder: what changed, when, and why.
GitHub is a website. It stores an online copy of that folder with its full history, and it can publish the folder as a website (GitHub Pages).
  • Undo anything. Every saved version is kept. If the agent makes a mess, you go back to the last good one.
  • See exactly what changed. Git shows the lines that were added or removed (a diff). That's how you review an agent's work.
  • Backup and share. Your work lives online, not just on your laptop. One link shares it, and you can work from any computer.
  • Free publishing. GitHub Pages turns the folder into a public website. No server needed.

Commit and push, concretely

There are two actions to remember. A commit takes a labelled snapshot of your folder and saves it on your laptop. A push uploads your new snapshots to GitHub, and only then does your live site update. It's like saving a draft with a note, then sending it. Try it:

Working with an agent: six principles

A coding agent is fast, capable and confident, and it only knows what you tell it. When something is missing, it fills the gap with a plausible guess. These principles keep you in charge. They apply to every tool and every task, not just this website.

  1. Give it context. Say what this folder is, who the result is for, and where it will run. "This folder is my GitHub Pages repo for a college course."
  2. Say what "done" looks like. Be concrete, and ask for one change at a time. Describe what you see, not what you guess. "On my phone the menu overlaps the title. Fix only the menu."
  3. Set limits. Say what it must not do, add, or invent. "Use only the text I give you. Plain HTML and CSS, no frameworks."
  4. Plan before it acts. For anything bigger than a small fix, ask for a plan first, or let it ask you questions. "Before editing, show me your plan, and ask me up to 3 questions about anything unclear."
  5. You review everything. Check the actual result yourself, in the browser, sentence by sentence. "Done!" from the agent is a claim, not proof. "List every file you changed and what you changed in each."
  6. Save often, undo freely. Commit whenever something works. If a change goes badly, go back to the last commit instead of arguing with the agent. "Undo your last change."

Your first request

Write it yourself. A few sentences that follow the principles are enough. Here's what one can look like:

Example first request
This folder is my GitHub Pages repo for a college course. Build a simple one-page personal website: an index.html with a linked style.css, plain HTML and CSS only. Include About, Interests and Project interests sections, using only the text I give below. Don't add facts, links or achievements I didn't write. Keep it readable on a phone. Add a footer saying "Built with [tool]. Text written by [my name]." Before editing anything, show me your plan and wait for my OK.

[paste your content here]

It's short, but every principle is there: context (line 1), done (the sections), limits (no invented facts, no frameworks), plan first (the last line). You'll do the reviewing and saving.

You are the reviewer

    

    

      
        
Read before you approveWhen the agent asks to run a command you don't understand, ask it: "What does that command do, and why do you need it?" If you're not sure, say no. You can always ask for another approach.

        
Never paste secretsNo passwords, API keys, or personal ID numbers in prompts or in the site. GitHub will handle sign-in itself.

        
Public means publicAnything you push to a public repo can be seen, copied, and archived, including in the commit history. Deleting a file later doesn't erase it from earlier commits.

        
Stay in the folderThe agent should only work in your repo folder. If it wants to touch files elsewhere on your computer, stop and ask why.

        
DiscloseYour footer credits the tool you used. That's the course AI-use policy in miniature: credit AI the way you'd credit a collaborator.

      
    

    

  


  
  

    
Stuck?

    
First ask your agent. Describe exactly what you see: "GitHub Desktop says 'rejected — fetch first'. What does that mean, and what should I click?" Then check here, then ask a neighbor, then raise your hand.

    
    
    

      

        The Code tab asks me to upgrade (Claude)
        
Claude Code needs a paid Claude plan (Pro or higher). Switch this guide to . It's included with ChatGPT plans, including Free with lower limits. Or pair with a neighbor today and sort out access later. Contact the teaching staff if cost is a barrier.

      

      

        I hit a usage limit
        
Limits reset after a few hours. Meanwhile: keep your requests small and specific (they use less), switch to the other tool, or make small text edits yourself. index.html is just a text file, and you can open it in any editor.

      

      

        I can't find my repo folder when selecting it in the agent
        
In GitHub Desktop: Repository → Show in Finder / Show in Explorer. The window title shows the path. By default it's Documents/GitHub/YOUR-USERNAME.github.io.

      

      

        The agent says it can't see my files, or describes a different folder
        
Ask it: "What is your current working directory?" If it's not your repo, start a new session and select the right folder (step 2).

      

      

        GitHub Desktop shows "No local changes" after the agent edited files
        
The agent was probably working in a different folder than the repo GitHub Desktop is tracking. Compare the two paths. Also check that the agent actually finished and saved (with Claude in Manual mode, did you click Accept?).

      

      

        My address shows a 404 "There isn't a GitHub Pages site here"
        
Check four things: (1) the repo is named exactly username.github.io with your username; (2) it's Public; (3) Settings → Pages is set to Deploy from a branch · main · / (root); (4) you've waited up to 10 minutes after your first push.

      

      

        My site shows the README instead of my page
        
GitHub Pages looks for a file named exactly index.html (all lowercase) at the top level of the repo. Check the file name and location on github.com. Also check that you pushed after committing.

      

      

        I pushed, but the live site still shows the old version
        
Wait 1–2 minutes, then hard-refresh: Cmd+Shift+R (Mac) or Ctrl+F5 (Windows). Check the Actions tab in your repo to see if the deployment is still running.

      

      

        The live page has no styling (plain black text), but it looked fine locally
        
Usually style.css wasn't committed, or the link in index.html uses a different capitalization (Style.css vs style.css). File names are case-sensitive on GitHub Pages but not on your Mac. Ask the agent: "Check that every file index.html links to exists with the exact same name."

      

      

        Push fails: "rejected" or "fetch first"
        
GitHub has a change your laptop doesn't, usually because you edited something on github.com. In GitHub Desktop, click Fetch origin, then Pull origin, then Push origin.

      

      

        The agent invented things about me
        
This is normal agent behavior, which is why you review. Ask: "Compare the page with the content I gave you and remove anything I didn't write." Then read it again yourself.

      

      

        (Windows) My file is called index.html.txt
        
Windows hides file extensions by default. In File Explorer: View → Show → File name extensions, then rename the file to index.html. Better: have the agent create the files, and this won't happen.

      

      

        I have privacy concerns about a public page
        
Share only what you're comfortable with. A photo and contact details aren't required. If you have concerns about hosting a public page at all, talk to your TA about an alternative.

      

      

        I (or the agent) broke the site. How do I go back?
        
If you haven't committed yet: in GitHub Desktop, right-click the changed file → Discard changes. If you already committed: open the History tab, right-click the bad commit → Revert changes in commit. This is why you commit often.

Words you'll hear

    

      
Repository (repo)
A project folder whose history Git tracks. Yours lives both on your laptop and on GitHub.

      
Clone
Copy a repo from GitHub to your laptop, keeping them connected.

      
Commit
A saved version with a message describing what changed. Like a save point in a game.

      
Push
Send your new commits from your laptop up to GitHub.

      
Pull / Fetch
Bring changes from GitHub down to your laptop.

      
Branch main
The main line of your project's history. Today you only use this one.

      
Diff
A view of exactly which lines were added (green) or removed (red).

      
GitHub Pages
GitHub's free hosting: it turns the files in a repo into a public website.

      
Permission mode
How much the agent may do without asking you first. Start cautious.

      
HTML / CSS
HTML is the content and structure of a page; CSS is how it looks. Both are plain text files.
